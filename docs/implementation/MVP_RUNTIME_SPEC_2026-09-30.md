# LIFTLY MVP 런타임 기능 명세

**상태:** CURRENT · Figma 최신 결정 반영  
**기준일:** 2026-09-30  
**적용 범위:** Figma `MVP_전체_와이어프레임`의 01~08 그룹

## 1. 이 문서의 역할

이 문서는 Figma의 화면 전환을 실제 앱 동작으로 구현하기 위한 최신 기능 계약이다.

- 화면의 모양·컴포넌트는 Figma를 따른다.
- 사용자 행동, 상태 변화, 저장 규칙은 이 문서를 따른다.
- 기존 구현 문서와 충돌하면 **이 문서의 최신 결정이 우선**한다.
- Android MVP, local-first(SQLite) + Supabase 동기화 구조를 전제로 한다.

## 2. 책임 분리

| 영역 | 프론트엔드 | 백엔드/데이터 |
| --- | --- | --- |
| 인증 | 로그인 상태, 온보딩 진입, 오류/재시도 UI | Google·Kakao ID 검증, 계정 식별·생성 |
| 루틴 | 폴더/루틴/운동 편집 폼, 입력 검증, 즉시 반영 | 루틴 정의 영속화·동기화 |
| 운동 진행 | 세트 체크, 시간, 타이머, 오프라인 복구, 종료/폐기 UI | 세션·세트 기록 저장, 여러 기기 동기화 |
| 분석 | 월 선택, 달력 상태, 집계 결과 렌더링 | 월별 운동일·볼륨·부위 분포·기록 변화 조회 |
| 설정 | 토글·선택 값, Android 권한 안내 | 사용자별 설정 보관 |
| 문의/이미지 | 입력·업로드 진행/실패 UI | Storage 업로드, 문의 메타데이터 저장 |

타이머의 초 단위 진행과 Android 휴식 종료 알림은 서버가 아니라 **클라이언트/Android 네이티브 기능**이 소유한다. 서버에는 완료된 기록과 사용자가 선택한 설정만 저장한다.

## 3. 공통 런타임 원칙

1. 모든 생성 데이터는 클라이언트 UUID를 먼저 발급해 SQLite에 저장하고, 네트워크가 가능할 때 Supabase로 동기화한다.
2. 운동 중 기록은 세트 입력·완료 때마다 저장한다. 앱 종료·백그라운드 뒤에도 같은 `active session`을 복구한다.
3. 저장/수정/삭제는 낙관적으로 화면에 반영하되, 동기화 실패는 재시도 대기 상태로 남긴다. 운동 기록을 네트워크 실패 때문에 버리지 않는다.
4. 삭제는 화면에서 즉시 사라지지만, 동기화 전까지는 삭제 대기 상태를 유지한다.
5. 한 계정에는 동시에 하나의 활성 운동 세션만 존재한다.
6. 시간은 저장 시 UTC, 표시 시 사용자의 로컬 시간대로 변환한다. 중량의 원본 단위와 정규화 kg 값을 함께 보관한다.

## 4. 핵심 데이터 모델

| 도메인 | 최소 엔터티 | 핵심 필드 |
| --- | --- | --- |
| 계정 | `profiles`, `user_settings` | user_id, 성별, 생년월일, 약관 동의 시각, 언어, 단위, 알림, 타이머 사운드 |
| 운동 라이브러리 | `exercises`, `custom_exercises` | 이름, 썸네일, 장비, 주/보조 근육, 기록 방식, 소유자 |
| 루틴 | `routine_folders`, `routines`, `routine_exercises`, `routine_sets` | 폴더명, 루틴명, 순서, 운동/세트 기본값 |
| 운동 세션 | `workout_sessions`, `workout_session_exercises`, `workout_sets` | started_at, ended_at, 상태, 운동 순서, 세트별 중량·횟수·완료 시각 |
| 분석 | 저장 테이블 대신 집계 조회 | 운동일, 총 볼륨, 세트 수, 운동 시간, 근육 부위별 비중, 개인 기록 |
| 지원 | `support_inquiries`, `media_assets` | 카테고리, 본문, 상태, 첨부 파일 경로 |

`workout_sessions.status`는 최소 `active`, `completed`, `discarded`를 사용한다. `discarded` 세션은 분석과 최근 운동에 포함하지 않는다.

## 5. 화면별 기능 계약

### 01 · 인증과 첫 설정

| 화면/행동 | 프론트 동작 | 백엔드/데이터 동작 |
| --- | --- | --- |
| 로그인 | Google/Kakao 인증 시작, 로딩·네트워크·서비스 오류 표시 및 재시도 | provider identity를 내부 user와 연결 |
| 첫 설정 | 성별·생년월일·약관 동의가 모두 유효할 때만 시작 CTA 활성 | `profiles`와 동의 시각 저장 |
| 재진입 | 미완료 계정은 Basic Info로, 완료 계정은 홈으로 라우팅 | onboarding 완료 여부 조회 |

### 02 · 루틴 홈

| 행동 | 프론트 동작 | 백엔드/데이터 동작 |
| --- | --- | --- |
| 빈 운동 시작 | 빈 `active session` 생성 후 운동 화면으로 이동 | 빈 세션 초안 저장 |
| 폴더 → 루틴 만들기 | 먼저 폴더명, 그다음 루틴명과 운동을 편집 | 폴더와 루틴을 별도 식별자로 저장 |
| 루틴 선택 | 상세에서 구성 확인 후 시작 | 루틴 정의 조회. 시작 시 세션에 스냅샷 복사 |
| 루틴 목록 | 폴더와 하위 루틴을 현재 정렬값으로 렌더링 | 사용자 소유 루틴만 조회 |

루틴을 시작한 뒤 세션에서 수정한 세트/운동은 기본적으로 루틴 원본을 바꾸지 않는다. `루틴에도 반영`을 명시적으로 선택했을 때만 원본을 갱신한다.

### 03 · 루틴 생성/편집

- 운동 추가는 04 검색 화면으로 이동한다.
- 저장은 폴더명, 루틴명, 최소 한 개의 운동이 유효할 때 가능하다.
- 세트는 MVP에서 순번·중량·횟수의 일반 세트만 지원한다.
- 삭제 확인의 승인 행동은 루틴과 하위 정의를 삭제 대기 처리하고 루틴 홈으로 돌아간다.
- 편집 취소/뒤로가기는 미저장 변경이 있을 때만 확인 화면을 띄운다.

### 04 · 운동 검색과 커스텀 운동

- 검색·장비 필터·부위 필터는 클라이언트 상태이며 결과 조회 조건으로 사용한다.
- 목록의 추가 컨트롤은 미선택 `+`, 선택 `check` 상태를 표시한다.
- 선택 확정은 선택 운동 목록을 03의 편집 초안으로 돌려준다.
- 커스텀 운동은 이름, 장비, 주/보조 근육, 기록 방식의 유효성 검사를 거쳐 저장한다.
- 운동 상세의 기록/성장 화면은 완료된 세션의 해당 운동 세트만 집계한다.

### 05 · 운동 진행

#### 활성 세션

- 헤더는 경과 시간과 더보기 액션을 표시한다. 운동이 일시정지 상태라면 경과 시간은 50% opacity로 표시한다.
- 세트 행을 완료하면 `completed_at`을 기록하고 자동 휴식 타이머를 즉시 시작한다.
- 세트별 중량/횟수 변경은 입력 완료 시점마다 세션 초안에 저장한다.
- 더보기 패널은 운동 종료, 운동 추가, 수동 타이머를 제공한다.
- 운동 추가는 운동 선택 화면으로 이동하고, 확정 시 현재 세션의 마지막 운동 뒤에 추가한다.
- 종료는 완료/미완료 확인을 거쳐 `completed`로 확정한다. 이탈/폐기는 `discarded`로 처리한다.

#### 자동 휴식 타이머

- 세트 완료 직후 바텀시트로 표시한다.
- 원형 프로그레스와 남은 시간, `− 15초 +` 컨트롤, `휴식 건너뛰기`만 제공한다.
- 자동 휴식에는 pause, reset, 별도 시작 액션이 없다.
- 오버레이 탭과 `휴식 건너뛰기`는 동일하게 타이머를 종료하고 운동 진행 화면으로 돌아간다.
- 진행 중 다른 세트를 완료하면 기존 타이머를 교체하고 새 세트 기준으로 다시 시작한다.
- 0초가 되면 시트를 닫고 Android 휴식 종료 알림을 보낸다. 알림 권한이 없더라도 운동 데이터 저장은 막지 않는다.

#### 수동 타이머

- 자동 휴식이 실행 중일 때는 시작할 수 없다.
- `타이머 시작 → 일시정지 → 계속 진행 / 초기화` 상태를 가진다.
- 수동 타이머의 시작·일시정지·초기화는 클라이언트 로컬 상태이며, 완료된 운동 기록에는 저장하지 않는다.

### 06 · 운동 완료

- 완료 확인 시 세션 종료 시각, 총 볼륨, 완료 세트, 운동 시간을 확정한다.
- 완료 화면은 확정된 세션 스냅샷만 보여준다. 이후 원본 루틴 변경으로 과거 결과가 바뀌면 안 된다.
- 완료 후 홈 또는 해당 날짜의 07D 세션 상세로 이동한다.

### 07 · 분석

| 행동 | 프론트 동작 | 백엔드/데이터 동작 |
| --- | --- | --- |
| 월 이동 | 달력 월을 전환하고 하단 요약을 같은 월로 갱신 | 월 범위 기준 집계 조회 |
| 날짜 선택 | 운동 1개면 07D, 2개 이상이면 07C 선택 목록으로 이동 | 로컬 날짜 기준 완료 세션 조회 |
| 부위 분포 상세 | 월간 부위 분포의 상세 목록 표시 | 완료 세트의 주/보조 근육 기준 집계 |
| 세션 상세 | 운동명, 썸네일, `50kg × 12회 × 3세트`처럼 묶인 수행 데이터 표시 | 세션 스냅샷 조회 |

달력 상태는 다음 세 가지를 구분한다: 운동한 날, 선택한 날, 오늘. 같은 날짜가 둘 이상이면 선택 상태는 07C에서 세션 선택 후 07D로 이어진다.

### 08 · 설정과 지원

- 단위 설정은 표시값만 kg/lb로 바꾼다. 저장 원본과 분석 정규화값은 유지한다.
- 휴식 타이머 알림은 앱 설정값과 Android 시스템 권한을 함께 확인한다. 시스템 권한이 없으면 적절한 시점에 권한 요청 또는 Android 설정 진입을 제공한다.
- 타이머 사운드는 다음 자동 휴식 종료부터 적용한다.
- 프로필 사진은 선택 → 1:1 크롭 → 업로드 → 프로필 반영 순서다. 업로드 실패 시 기존 이미지를 유지한다.
- 계정 삭제는 재확인 후 서버 계정 삭제 요청과 로컬 데이터 폐기를 수행하고 로그인으로 이동한다.
- 문의는 카테고리·본문·첨부파일을 저장하며 전송 실패 시 재시도할 수 있다.

## 6. 프론트엔드 상태와 API 계약

### 화면 상태

- **서버/동기화 상태:** `idle`, `loading`, `saving`, `sync_pending`, `error`
- **폼 상태:** `pristine`, `dirty`, `valid`, `invalid`
- **세션 상태:** `none`, `active`, `resting`, `paused`, `completed`, `discarded`
- **타이머 상태:** `idle`, `running`, `paused`, `ended`

### 필수 명령

| 명령 | 결과 |
| --- | --- |
| `createRoutineFolder`, `createRoutine`, `updateRoutine`, `deleteRoutine` | 루틴 정의 변경 후 로컬 저장·동기화 예약 |
| `searchExercises`, `createCustomExercise`, `updateCustomExercise`, `deleteCustomExercise` | 라이브러리 결과 갱신 |
| `startWorkout`, `addExerciseToSession`, `completeSet`, `updateSet`, `endWorkout`, `discardWorkout` | 활성 세션 상태 갱신 |
| `startRestTimer`, `adjustRestTimer`, `skipRestTimer` | 로컬/Android 타이머 갱신 |
| `startManualTimer`, `pauseManualTimer`, `resumeManualTimer`, `resetManualTimer` | 로컬 수동 타이머 갱신 |
| `getMonthlyAnalysis`, `getDaySessions`, `getSessionDetail` | 분석·기록 화면 데이터 조회 |
| `updateSettings`, `uploadProfileImage`, `submitSupportInquiry` | 사용자 설정/지원 데이터 갱신 |

각 명령은 UI 컴포넌트가 직접 Supabase를 호출하지 않고, repository/use-case 계층을 통해 실행한다.

## 7. 구현 완료 기준

1. Figma의 01~08 실제 진입·뒤로가기·저장·취소·확정 동선이 앱에서도 동일하다.
2. 네트워크 없이 운동 시작, 세트 완료, 자동 휴식, 종료, 다음 실행 복구가 가능하다.
3. 동기화가 늦거나 실패해도 완료 세트와 운동 세션이 사라지지 않는다.
4. 분석은 `completed` 세션만 반영하며 폐기 세션은 제외한다.
5. 자동 휴식과 수동 타이머는 동시에 실행되지 않는다.
6. 월 이동·날짜 선택·세션 상세가 같은 기준 시간대와 데이터 범위를 사용한다.
7. 삭제·계정 삭제·문의 전송 실패에는 명시적 사용자 피드백과 재시도/복귀 경로가 있다.
